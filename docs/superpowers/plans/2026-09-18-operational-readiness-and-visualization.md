# 운영 준비도·데이터 활용 시각화 구현 계획

## 목표

미수집·승인대기·수동입력 자료를 숨기지 않고 현재 수집 가능성, 필요한 인증정보, 적재 수량, 활용 분석과 다음 조치를 한 화면에서 보여준다. Ollama 로컬 모델과 외부 시연 서버는 Windows 바탕화면 실행기 한 번으로 준비·실행되며, 구현과 검증 이력은 단계별 Git 커밋으로 남긴다.

## 1. 데이터 준비도 API

- 각 출처의 자동 API/무인증 자동/수동 다운로드/파생 자료 구분을 코드 레지스트리로 관리한다.
- 자격정보 설정 여부는 boolean으로만 반환하고 키 원문은 노출하지 않는다.
- 실제 DB의 원본·정규화 행 수, 현재 상태, 차단 이유, 수집 범위, 활용 산출물과 다음 행동을 `/api/readiness`로 반환한다.
- K-apt, KMA, SGIS, VWorld, 건축HUB와 수동 자료를 모두 포함하고 중복된 구형 카탈로그 항목은 명확히 구분한다.
- API 계약과 키 비노출 테스트를 먼저 작성한다.

## 2. 데이터 수집·활용 시각화

- 수집 데이터 화면 상단에 자동수집 가능/키·승인 필요/수동 원본 필요/수집 완료 상태를 시각 카드로 표시한다.
- 공급처 → 원본 보존 → 정규화/PostGIS → 지도·탄소·모델·보고서 흐름을 반응형 파이프라인으로 표시한다.
- 각 공급처 카드에 현재 행 수, 인증 상태, 단계별 호출량, 활용 기능과 다음 행동을 표시한다.
- 0행, 실제 0값, 비공개·결측을 혼동하지 않는 문구를 유지한다.
- 프런트엔드 테스트와 모바일 브라우저 검증을 추가한다.

## 3. 로컬 LLM 운영 구조

- 기존 Ollama `qwen2.5:1.5b`를 기본 모델로 유지하고 모델 상태·설치 여부·허용 역할을 API와 화면에 표시한다.
- LLM은 검증된 근거 ID 선택과 한국어 보고서 요약만 수행하고 수치 계산은 기존 계산 엔진이 담당한다.
- 모델 설치/확인 명령을 독립 스크립트로 분리하고 배포 실행기가 이를 호출한다.
- 연결 실패 시 검증된 서식 보고서로 자동 대체하는 기존 동작을 보존한다.

## 4. 원클릭 Windows 실행기

- Docker Desktop이 꺼져 있으면 시작하고 엔진이 준비될 때까지 기다린다.
- DB/API/worker/frontend/Ollama를 시작하고 모델을 준비한 뒤 인증 gateway와 Cloudflare Quick Tunnel을 시작한다.
- 현재 공개 URL을 검증하고 기본 브라우저로 연다. 로그와 접속정보 파일 위치를 안내한다.
- 저장소에 재사용 가능한 CMD/PowerShell 실행기를 넣고 실제 바탕화면에도 실행 CMD를 만든다.
- 기존 DB 볼륨, 원본, API 키를 삭제하거나 덮어쓰지 않는다.

## 5. 보고서·검증·배포

- 최종 목표, 완료 기능, 외부 입력이 필요한 항목, 검증 결과, 운영 절차와 우선순위를 한국어 보고서로 정리한다.
- 백엔드 전체 테스트, 프런트엔드 테스트·빌드, 로컬 AI 상태, 브라우저 흐름, 공개 URL을 검증한다.
- 의미 있는 구현 단계마다 커밋하고 `origin/main`에 푸시한다.
