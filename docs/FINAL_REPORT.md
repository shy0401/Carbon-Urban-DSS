## 실제 자료와 범위

전주시 호성동 **LG동아 아파트 인근 `cell_968500_1762000`**, EPSG:5179 정렬 500×500m, 250,000m²를 공간 후보로 선정했다. 셀 내 OSM 아파트 건물은 49개다. 이는 행정상 단지 동수나 공식 전체 건물 모집단이 아니다. 에너지 완전성에 따른 최종 선정은 보류한다.

DB에는 법정동 코드 86행, OSM 건물 2,171개, 경계 1개, 파생 격자 916개, 기상 12개월, K-apt 364단지(상세 8개), 전주시 준공 공동주택 595개/공사 중 14개, 적용 가능한 전력계수 1개가 있다. 에너지·인구·법정 용도지역·공식 건축물대장 적재는 0행이다. [출처와 기간](DATA_SOURCES.md)을 분리 기록했다.

## 구현 및 방법

FastAPI/PostGIS/Celery/Redis, React/MapLibre/ECharts를 Docker로 실행한다. 원본·정규화·작업·출처·오류를 보존하며 기간 수집, 업로드 미리보기/매핑, 품질 지표, 7종 지도 지표, 시뮬레이션, 모델 상태, 오프라인 모드를 제공한다.

FAR=계획 연면적/개발부지×100, BCR=계획 건축면적/개발부지×100. 분석 셀과 개발부지는 구분한다. 매칭된 관측의 월별 에너지/동일 범위 연면적을 계획 면적에 적용하고 효율·태양광 가정을 분리한다. 세대·인구·녹지·수용량 제약을 검사한다. 전력계수는 GIR 소비단 0.4541 kgCO2eq/kWh이며 2025 소급 적용은 프로젝트 선택이다. 가스 기준이 미확정이면 전체 탄소를 계산하지 않는다.

최적화는 제약을 만족하는 이산 층수·동수 조합을 결정론적으로 비교한다. 법적 적합성 판정은 아니다. 기준 관측이 없으면 추천안을 반환하지 않는다. 원단위, ElasticNet, Random Forest, Histogram Gradient Boosting, spline 회귀 비교와 공간 블록 검증을 구현했다. 현재 관측 0행으로 **INSUFFICIENT_TRAINING_DATA**, MAE/RMSE/R²/NMAE/sMAPE는 모두 미산출이다. 검증된 실제 예측 성능은 없다.

## 검증 및 남은 조치

백엔드 **52/52**, 프런트엔드 **15/15**, Chromium **9/9**, 최종 실패 0/pageerror 0. 별도 신규 DB/Redis에 실제 원본을 복원하고 행수를 비교했다. 운영 빌드와 오프라인 도형 렌더링을 확인했다. [검증 명령과 한계](TESTING.md)를 제공한다.

- `.env`의 `DATA_GO_KR_SERVICE_KEY`를 유효한 키로 교체하고 에너지·건축물대장·KMA의 개별 활용 승인을 확인해야 한다. 제공 키는 에너지 API 오류 30으로 거부되었다.
- VWorld 키/공식 용도지역, SGIS 자격/인구 원본, NGII 격자 원본이 필요하다. 미확보 소스가 키 입력만으로 모두 자동 연결된다고 보장하지 않는다. 수동 업로드 경로는 제공한다.
- 가스 열량 기준·GWP·계수 확정, K-apt 상세 시점·정확한 지번·동일 범위 연면적 확인이 필요하다. 단지 중심점 매칭은 지적 면적에 따른 에너지 배분이 아니다.

키 교체 후 `docker compose up -d --force-recreate api worker`를 실행하고 온라인 모드에서 재수집한다. 이후 공간 매칭·월별 완전성·기준면적·모델 검증을 다시 확인해야 실제 탄소 영향과 최적안을 제시할 수 있다. 현재는 자료 출처·공간 분석·면적 시뮬레이션·결측 처리·오프라인 시연까지 재현 가능하다.

## 2026-09-14 기능 보완 및 최신 검증

최신 보완 내역과 미구현 항목은 [IMPLEMENTATION_UPDATE.md](IMPLEMENTATION_UPDATE.md)를 따른다. 이번 결과는 백엔드 63개, 프런트엔드 17개, 기존 E2E 9개와 보완 E2E 9개 통과이며 브라우저 실행 오류는 0건이다. 실제 로컬 Qwen 모델의 근거 선정 및 원문 검증도 통과했다. 이전 날짜의 신규 DB 복원 결과와 구분한다.

추가 E2E: `node scripts/e2e-refined.cjs`. 기본 웹 주소는 127.0.0.1:5173이며 결과는 `data/validation/refined/`에 저장한다. 보고서의 비교·다운로드·인쇄, 모바일 및 오류 상태를 포함한다. 실제 에너지 관측·탄소 감축·예측 성능 검증은 자료 확보 후 수행해야 한다.
