# 지역 개발 시뮬레이션 (/area)

2026-09-25 추가. 웹 메뉴 **지역 시뮬레이션**.

## 할 수 있는 일

1. 구역을 고릅니다.
   - 행정동 35개 (목록에서 고르거나 지도에서 동을 누름)
   - 반경 100~5,000m (지도를 누른 곳이 중심)
   - 직접 그린 다각형
   - 용도지역 (주거·상업·공업·녹지·관리) 격자 묶음
   - 예비 선정 격자
2. 과거와 현재를 연도별로 봅니다 (기본 2015~2025). 슬라이더와 재생 버튼으로 연도를 바꾸면 지도의 단지가 준공 전 빈 원에서 준공 뒤 채운 원으로 바뀝니다.
   - 기존 단지: 회색
   - 개발 연도 단지: 호박색
   - 이후 단지: 보라
   - 그 해 준공: 검은 테
3. 개발 전후 영향을 봅니다. 개발 연도(자동 또는 선택)의 앞뒤 1~5년 평균을 비교하고, 개발 연도 자체는 전환기라 뺍니다.
   - 관측: 12개월 완전 지번만 씁니다. 지역 합계 변화, 기존 단지만의 변화, 신규 단지 비중을 봅니다.
   - 추정: 준공 단지 연면적 × 전주 관측 원단위로 냅니다. "이 개발만의 증가"는 직전 연도 재고 대비로 계산해서 다른 해의 개발과 섞이지 않습니다.
   - 맥락: 난방도일·냉방도일·인구의 전후 평균입니다.
4. 미래 개발의 감축 노력을 봅니다. 계획 조건과 목표 감축률(0~100%, 화면 입력)을 넣습니다. 계획 조건은 추가 연면적 또는 층수×동수×건축면적, 그리고 철거 연면적입니다.
   - 기준, 개발 후(추가 대책 없음), 목표 탄소를 비교합니다.
   - 필요 감축량을 보여 줍니다.
   - 신축만 개선할 때의 필요율을 보여 줍니다. 100%를 넘으면 불가로 표시하고, 신축 원단위 목표도 함께 보여 줍니다.
   - 지역 전체 효율 개선률과 재생에너지 상쇄 kWh를 보여 줍니다.
   - 태양광 kW는 사용자가 넣은 kW당 연 발전량으로, 비워 두면 지역 수평면 일사량 × 성능비 0.80 추정값으로 계산합니다([기준 5.13](DATA_STANDARD.md#513-태양광-연-발전량-추정)). 추정이면 결과와 보고서에 '(추정값)'과 연도·출처를 붙입니다.
   - 목표별 곡선을 그립니다.
5. 보고서를 만듭니다. 근거 문장으로 요약을 씁니다. 로컬 AI를 켜면 모델 문장을 검증해서 숫자·연도·증감 방향이 하나라도 다르면 게시하지 않고 서식으로 바꿉니다. 결과는 저장되고 마크다운으로 내려받을 수 있습니다. 목록은 기존 검토 보고서와 분리됩니다.

## 데이터 규칙

- 관측이 없는 연도는 0이 아니라 "자료 없음"(해치)으로 둡니다. 추정선은 따로 그리고 "추정" 배지를 붙입니다.
- 행정동 통계(인구)는 격자·반경에 배분하지 않습니다. 겹치는 행정동 값은 참고로만 씁니다.
- 탄소 계수는 최신 등록 전력 계수를 모든 연도에 똑같이 적용하고, 화면과 보고서에 이 사실을 적습니다. 가스는 계수를 확정한 뒤 넣습니다.
- 개발 이력은 K-apt 사용승인일에서 가져옵니다. 연면적 이상치는 제외합니다.
- 기준 부하는 지역 관측이 있으면 관측값(OBSERVED)을 쓰고, 없으면 연면적 × 전주 원단위 추정(ESTIMATED)을 씁니다. 화면에 어느 쪽인지 배지로 표시합니다.

## 빠진 자료 채우기

웹 **수집 데이터 → 빠진 자료 전부 수집** 버튼으로 실행합니다. PC 명령으로도 같은 일을 합니다. 명령은 백업을 먼저 만듭니다.

```powershell
scripts\dss.cmd CollectAll -FromYear 2015 -ToYear 2025
```

`CollectHistory`도 같은 명령입니다.

받는 순서:

1. 해마다: SGIS → ASOS(실패 시 ERA5-Land) → K-apt 월별 에너지 → 건축HUB 지번 에너지
2. 마지막에 한 번: VWorld 용도지역 → 도로명주소 건물 → 연속지적 전체 → 건축물대장 표제부

건너뛰는 항목 (호출하지 않음):

- DB에 이미 있는 항목. 예: 그 해 ASOS 완전월 12개, 그 해 SGIS 인구, 전체 범위 수집 완료된 레이어.
- 키가 없거나 형식이 틀렸거나 최근에 거절된 데이터셋.

K-apt는 단지별로 사용승인 이전 달을 건너뜁니다. 성공한 응답은 캐시되어 다시 요청하지 않습니다.

일일 호출 한도에 걸리면 그 데이터셋만 멈춥니다.

- 웹 작업은 `WAITING` 상태가 되고, 다음 날 00:20(KST)에 스스로 이어서 받습니다. Celery ETA를 쓰며, 작업자가 재시작되면 상태 조회 시 다시 큐에 넣습니다.
- **지금 바로 다시 시도** 버튼으로 즉시 재시작할 수 있습니다.
- 웹 작업과 PC 명령이 동시에 돌지 않도록 Redis 잠금을 겁니다.

진행 기록은 `data/ops/history-progress.json`에 남습니다. 계획(자료×연도 상태표)은 `GET /api/collection/missing`으로 보고, 시작은 `POST /api/collection/missing`으로 합니다.

API로 받을 수 없는 자료는 화면에 목록과 신청처를 보여 줍니다. 받은 파일은 수동 업로드로 가져옵니다.

- SGIS 500m 격자 (1km 격자 2024는 공공데이터포털 파일로 적용 완료. [SGIS_GRID.md](SGIS_GRID.md))
- 가스 배출계수
- 연도별 전력 배출계수
- 선도소프트 100m 격자

### 건축물대장 표제부 (2026-09-25 추가)

`getBrTitleInfo`로 전주시 법정동 83곳의 모든 페이지를 100동씩 받습니다. 저장하는 항목:

- 연면적·건축면적·대지면적, 용적률·건폐율(현재값)
- 지상·지하 층수, 높이, 구조, 주용도
- 사용승인일·허가일·착공일
- 에너지효율등급, 에너지절감률, EPI, 녹색건축·지능형건축 등급
- 세대·가구·호수

빈 값은 0이 아니라 null로 둡니다. PNU는 대지구분을 연속지적 형식(1 일반, 2 산)으로 바꿔 만듭니다.

격자 연결 순서:

1. 연속지적 필지의 내부 대표점 (PostGIS)
2. 같은 지번의 K-apt 단지

지역 화면의 **모든 건물의 개발 이력(건축물대장)** 차트는 격자 기준으로 용도군별 사용승인 연면적을 보여 줍니다. 보고서 근거 문장에도 들어갑니다.

### 지역 특성 (SGIS 1km 격자, 2026-09-25 추가)

구역이 걸친 공식 1km 격자 전체의 인구·가구·주택·사업체·종사자와 비율, 분포를 보여 줍니다. 비율은 65세 이상, 1인가구, 2000년 이전 주택, 아파트입니다. 분포는 주택 건축연도·유형·규모, 가구 구성, 산업별 종사자입니다.

- 합계는 1km 격자 전체 값이라 구역보다 넓습니다. 화면에 구역이 그 격자 면적의 몇 %인지 적습니다.
- 면적 비례 인구는 추정 배지를 붙여 따로 둡니다.
- 비밀보호 잡음(±7)과 "통계 없음 ≠ 0" 규칙을 적용합니다.
- 보고서 근거 문장과 마크다운 표에도 들어갑니다.

자세한 내용은 [SGIS_GRID.md](SGIS_GRID.md)에 있습니다.

## API

| 메서드 | 경로 | 내용 |
|---|---|---|
| GET | `/api/areas/options` | 행정동 목록과 경계, 용도지역별 격자 수, 관측 연도, 기준 격자 |
| POST | `/api/areas/analyze` | `{area, from_year, to_year, event_year?, window, plan?, target_pct?, pv_yield_kwh_per_kw?}` → history, before_after, effort, grid_features, facts |
| GET | `/api/areas/collection` | 과거 수집 진행 |
| POST / GET | `/api/area-reports`, `/{id}`, `/{id}/markdown` | 지역 보고서 |
