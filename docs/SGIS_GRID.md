# SGIS 격자 통계 1km (2024) 적용

2026-09-25 추가.

## 원본

공공데이터포털 [국가데이터처_SGIS 격자 통계 및 경계](https://www.data.go.kr/data/15141768/fileData.do)의 2025-06-30 공개본을 씁니다. 기준시점은 2024년 6월 30일입니다.

패키지 구성:

- `1. 통계`: `<연도>년_<부문>_<100km 블록>_1K.csv`. 열은 기준연도, 격자코드, 통계항목, 통계값이고 CP949입니다.
- `2. 경계`: `grid_<블록>_1K.shp`. EPSG:5179 1km 정사각형이고 필드는 `GRID_CD`입니다.
- `3. 코드집`: 통계항목 코드와 이름.
- `4. (참고1)`: SGIS 소지역 통계 이용매뉴얼.

이 패키지는 **1km 격자만** 제공합니다. 500m·100m 격자 통계는 SGIS 자료신청이 필요합니다. 500m는 총괄 항목만 제공되며, 신청해 받은 500m 통계는 [아래 절](#sgis-500m-격자-통계-자료제공-신청분-2026-09-29-적용)에서 적용했습니다.

## 격자코드

코드 모양은 `<x블록><y블록><XX><YY>`입니다(예: `다마6862`). 블록 글자 순서는 가나다라마바사아입니다.

- x = 700000 + 100000 × (x블록 순서) + 1000 × XX
- y = 1300000 + 100000 × (y블록 순서) + 1000 × YY

위 식은 격자의 왼쪽 아래 모서리(EPSG:5179)입니다. 전주는 `다마` 블록 안에 있습니다.

프로젝트 500m 격자(`cell_<x>_<y>`, 왼쪽 아래 모서리)는 1km 격자 안에 정확히 4개씩 들어갑니다. 그래서 500m 격자의 소속 1km 격자는 좌표만으로 정해집니다.

## 자르기와 가져오기

1. `scripts/sgis/extract_sgis_grid.py`가 전주 범위(EPSG:5179 954000~977000, 1748000~1768000)만 잘라 `data/raw/sgis_grid_1k/<기준연도>/`에 둡니다.
   - 만드는 파일: `cells.csv`, `stats.csv`, `items.json`, `manifest.json`
   - 모든 경계 도형이 코드에서 계산한 정사각형과 같은지 확인하고, 다르면 중단합니다.
   - 표준 라이브러리만 씁니다. 코드집 이름은 openpyxl이 있을 때만 읽습니다.
   - 2024년 결과: 1km 격자 460개, 통계값 49,270행, 이름이 붙은 항목 326개.
2. API가 시작할 때 `import_sgis_grid`가 번들을 `sgis_grid_cells`·`sgis_grid_stats` 테이블에 넣습니다. 같은 행 수로 이미 들어 있으면 건너뜁니다.
3. 수동으로 다시 넣으려면 아래 명령을 씁니다.

```powershell
docker compose run --rm --no-deps -v "${PWD}:/work" -w /work api python scripts/sgis/extract_sgis_grid.py --source "국가데이터처_SGIS 격자 통계 및 경계_20250630/국가데이터처_SGIS 격자 통계 및 경계"
docker compose exec api python -m app.cli import-sgis-grid --force
```

원본 패키지 폴더는 `.gitignore`(`국가데이터처_SGIS*/`)로 빠지고, 잘라 둔 번들은 `data/raw/`라 git에는 들어가지 않습니다. 팀 번들(`scripts\dss.cmd ExportBundle`)에는 DB와 `data/raw`가 같이 들어갑니다.

## 표시 규칙

- **잡음**
  - 인구·가구·주택: 5 미만 값은 0 또는 5로 확률 대체되고, 그 이상은 최대 ±7의 잡음이 있습니다.
  - 사업체·종사자: 3 미만 값은 0 또는 3으로 대체되고, 그 이상은 ±4입니다.
  - 화면과 보고서에 이 사실을 적습니다. 0이나 5인 총계는 "5 미만일 수 있는 대체값"으로 표시합니다.
- **행이 없는 격자·항목**은 통계 없음입니다. 0으로 채우지 않습니다. 지도에서는 결측(해치)입니다.
- 세부 항목의 합은 총계와 같지 않습니다. 총계는 `to_*` 항목을 씁니다. 구성비는 그 분포의 항목 합 기준입니다.
- 비율은 기준(연령별 인구 합·총가구·주택 합)이 20 미만이면 계산하지 않습니다.
- **500m 격자**에는 소속 1km 격자의 값·밀도·비율을 붙입니다. 개수를 4로 나누지 않습니다. 1km 격자가 1km²라서 총계가 곧 밀도(/km²)입니다.
- **지역 시뮬레이션**
  - 관측: 구역이 걸친 1km 격자 전체의 합입니다. 구역보다 넓은 범위이며, 구역이 그 격자 면적의 몇 %인지 함께 적습니다.
  - 추정: 면적 비례 인구·가구입니다(1km 값 × 구역 안 500m 격자 수 ÷ 4). `ESTIMATED`로 따로 표시합니다.
- 행정동 SGIS 통계(API)는 그대로 행정동 값으로 두고, 격자 값과 섞지 않습니다.

## API와 화면

- `GET /api/sgis-grid/meta`: 기준연도, 격자 수, 행 수, 번들 목록, 규칙.
- `GET /api/map`
  - 격자마다 `sgis1k_code/year/status`, `sgis1k_population/households/housing/businesses/workers`를 붙입니다.
  - 밀도·비율로 `sgis_pop_density`, `sgis_housing_density`, `sgis_worker_density`, `sgis_elderly_pct`, `sgis_single_household_pct`, `sgis_old_housing_pct`, `sgis_apartment_pct`를 붙입니다.
  - 전체 설명은 `sgis_grid`에 있습니다.
- 대시보드 `context.sgis_grid`: 선택 격자의 소속 1km 격자 요약(분포 포함).
- `POST /api/areas/analyze`의 `history.sgis_grid`: `overlap`(관측 합계), `estimated`(추정), `coverage_pct`.
- 근거 문장
  - 격자 보고서: `context_sgis_grid`
  - 지역 보고서: `sgis_grid`, `sgis_grid_shares`
  - 지역 보고서 마크다운에는 "지역 특성" 표가 들어갑니다.
- 화면
  - 지도 분석 지표 묶음 "인구·주택 (SGIS 1km)" 7개와 격자 상세
  - 대시보드 "인구·주택" 패널
  - 지역 시뮬레이션 "지역 특성"
  - 사용 방법 `#sgis`

## 공식 500m 격자 경계·코드 (SGIS OpenAPI, 2026-09-27)

SGIS OpenAPI `grid/data.geojson`(`adm_cd`=시군구 코드, `grid_level_div=500m`)은 시군구 안의 **공식 500m 격자 경계와 코드**를 준다(통계값은 없음). 코드는 1km 코드에 500m 반쪽을 뜻하는 글자를 붙인 꼴이다: `다마62a48a` = 1km 격자 `다마6248`의 x 아래쪽(a)·y 아래쪽(a) 반쪽, `b`는 +500m. 경계는 EPSG:5179 좌표 500m 배수에 맞춰져 있어 프로젝트 격자 `cell_<x>_<y>`와 왼쪽 아래 모서리가 같으면 같은 칸이다.

- 수집: '빠진 자료 전부 수집'의 `sgis_grid_500m` 항목(한 번 받는 자료). `sgis_official_grid_cells` 테이블에 저장하고, 지도 격자 상세와 `/api/map`의 `sgis500_code`에 공식 코드를 표시한다.
- 검증: 코드의 a/b 글자와 경계 좌표가 어긋나는 칸 수를 세어 품질 문구에 적는다(0이어야 정상).
- 통계값: 500m 격자의 통계값은 공개 API·파일에 없어 SGIS 자료제공으로 신청해 받았다(2026-09-29 적용, 아래 절). 받은 파일의 격자코드가 위 코드와 같은 꼴이라 그대로 결합된다.


## SGIS 500m 격자 통계 (자료제공 신청분, 2026-09-29 적용)

SGIS 자료제공으로 받은 전국 500m 격자 통계를 넣었습니다. 받은 묶음은 `data/raw/sgis_grid_500m/`에 풀어 둡니다(git에는 들어가지 않음).

- 파일: `_census_reqdoc_<번호>/<연도>년_<인구|가구|주택|사업체|종사자>_<100km 블록>_500M.csv`. 머리줄 없이 `기준연도,격자코드,통계항목,값`이고 CP949입니다. 같은 폴더의 `_1K.csv`(1km)와 `_grid_border_*`(경계 SHP)는 읽지 않습니다.
- 격자코드: `다마62a48a`처럼 1km 코드에 x·y 반쪽(a = 아래·왼쪽, b = +500m)을 붙인 꼴입니다. 프로젝트 격자 `cell_<x>_<y>`와 왼쪽 아래 모서리가 같으므로 좌표에서 바로 코드를 계산해 붙입니다.
- 항목: 500m는 **총괄 항목만** 있습니다(`ref_code/statistics_code.xls` '격자' 시트). 총인구·남·여(`to_in_001/007/008`), 총가구(`to_ga_001`), 총주택(`to_ho_001`), 총사업체(`to_fa_010`), 총종사자(`to_em_020`). 연령·주택유형·건축연도 비율은 계속 1km 값을 씁니다.
- 연도: 2000·2005·2010은 인구만, 2015~2024는 다섯 주제. 이용안내에 없는 `9023년` 파일 24개는 읽지 않습니다.
- 비밀보호(`ref_code/statistics_guide.hwp`): 인구 부문 5 미만은 0 또는 5, 사업체 부문 3 미만은 0 또는 3으로 확률 대체하고, 그 이상 값에도 최대 ±7(사업체 ±4) 잡음이 있습니다. 화면은 값을 "잡음 포함 공식 통계"로 보여 주고 0·5(0·3)는 "작은 값(대체 가능)"으로 표시합니다. 파일에 행이 없는 격자·항목은 **통계 없음**이며 0으로 채우지 않습니다.

### 가져오기

```powershell
docker compose exec -T api python -m app.cli import-sgis-grid500          # 바뀐 연도만
docker compose exec -T api python -m app.cli import-sgis-grid500 --force  # 전부 다시
```

API가 시작할 때도 같은 가져오기를 백그라운드로 돌립니다. 파일 이름·크기와 행 수가 그대로인 연도는 건너뛰고(`data/raw/sgis_grid_500m/.imported.json`), API와 CLI가 동시에 돌면 PostgreSQL advisory lock으로 한쪽이 기다립니다. 결과는 `sgis_grid500_values`(연도·격자코드마다 한 행) 테이블입니다.

PC 적재 결과(2026-09-29): 13개 연도 2,368,172행, 111초. 2024년 196,384칸(인구 184,870 · 가구 183,028 · 주택 172,965 · 종사자 130,032칸), 2015년 182,610칸, 2000년 153,998칸. 2024년 총인구 합 50,787,885명(제주 블록은 받은 묶음에 없음).

### 받은 묶음에 없는 파일

13개 블록 × 5개 주제 중 아래가 빠져 있습니다(압축 파일 안에도 없음). 이 칸은 '통계 없음'으로 나오고, 수집 화면의 수동 자료 목록에 "빠진 파일 재신청"으로 뜹니다.

| 주제 | 블록 | 연도 | 영향 |
|---|---|---|---|
| 주택 | 다마 | 2015~2022 | 전주·완주 등 다마 블록의 2022년 이전 주택. 2023·2024는 있음 |
| 사업체 | 다마 | 2015~2024 | 다마 블록 사업체 수 전부 |
| 종사자 | 다마 | 2015~2024 | 다마 블록 종사자 수 전부 (전주 지도의 500m 종사자는 비어 있음, 1km 값은 있음) |

주택 격자 수가 2022년 154,071칸에서 2023년 173,703칸으로 뛰는 것도 다마 블록 파일이 2023년부터만 있어서입니다. 연도별 주택 추이는 블록을 맞춰 비교해야 합니다. 인구 증감률은 모든 블록·연도가 있는 인구만 씁니다.

### 화면과 API

- `GET /api/map`: 격자마다 `sgis500_status`(OBSERVED | NO_STAT), `sgis500_year`, `sgis500_population/households/housing/businesses/workers`, `sgis500_pop_density`(×4), `sgis500_base_year`(2015), `sgis500_base_population`, `sgis500_pop_change_pct`(두 해 모두 20명 이상일 때만), `sgis500_small`. 요약은 `sgis_grid500`.
- `GET /api/sgis-grid/500m/meta`: 연도별 격자 수·항목별 칸 수. `GET /api/sgis-grid/500m/cell/{cell_id 또는 500m 코드}`: 그 격자의 연도별 값.
- 시·군·구 지도: 지표 묶음 "인구·주택 (SGIS 500m)"(인구·가구·주택·종사자·인구 증감률)과 격자 상세의 "SGIS 500m 격자 자체" 절(연도별 인구 선, 연도별 값 표). 기본 지도(전국 공통 자료만 있는 시·군·구)의 첫 지표는 500m 인구입니다.
- 읍면동: 500m 주택·종사자는 겹친 비율로 더하고, 인구 증감률은 2015년 인구로 가중 평균(= 동 전체 증감률)합니다. 인구·가구 자체는 계속 SGIS 행정동 공식 값을 씁니다.
- 시·도 지도: 지표 묶음 "인구·주택 (SGIS 500m 격자 자체)"를 더했고, 500m 통계가 있으면 첫 지표가 500m 인구입니다. 1km 비율 지표와 K-apt 지표는 그대로입니다.
- PC 확인(2026-09-29): 전주시 916격자 중 674격자 관측(인구 합 657,370명, 인구 증감률 467격자), 수원시 559격자 중 471격자, 완주군 3,605격자 중 1,646격자. 전주 인구 최다 격자 `다마66b64a`는 2015년 13명 → 2018년 6,664명 → 2024년 8,466명으로, 2015년 이후 새로 개발된 곳으로 보입니다.
