# Carbon Urban DSS 구현·연동 현황

- 작성일: 2026-09-18
- 코드 기준: `main` 브랜치 `7a00933`
- 데이터 수량 기준: 2026-09-14 마지막 검증 DB

이 문서는 기능의 **코드 구현 여부**, **실데이터 적재·검증 여부**, **외부 승인·API 키 필요 여부**를 구분한다. 작성 시점에는 Docker 실행 환경을 다시 조회할 수 없어 아래 수량은 마지막 검증 결과를 사용했다. `0행`은 사용량이 0이라는 뜻이 아니라 자료가 아직 확보되지 않았다는 뜻이다.

## 한눈에 보는 상태

| 구분 | 의미 | 대표 항목 |
|---|---|---|
| 구현·검증 완료 | 화면과 백엔드가 연결되어 있고 실데이터 또는 결측 처리까지 검증됨 | 지도, 수집 이력, 시나리오, 보고서, K-apt 기본정보 |
| 키·승인 후 실행 가능 | 수집 어댑터가 이미 있으며 유효한 키와 서비스별 활용 승인만 필요 | 건물에너지, 건축물대장, KMA ASOS |
| 추가 개발 필요 | 키나 파일만 넣어서는 자동 연결되지 않으며 전용 수집·정규화·검증 코드가 필요 | VWorld, SGIS, 기업 100m 탄소격자 |

## 1. 현재까지 구현한 부분

### 1.1 서비스와 데이터 관리

- Docker Compose로 PostGIS, Redis, FastAPI, Celery worker, React/Nginx를 함께 실행한다. DB와 원본 캐시는 컨테이너를 재시작해도 보존한다.
- 수집 요청, 비동기 작업 상태, 실패 사유, 원본 파일 위치, 요청 파라미터, 수집 시점과 정규화 행 수를 기록한다.
- 온라인/오프라인 모드를 제공한다. 오프라인 모드는 저장된 DB와 원본만 사용하며 외부 수집을 차단한다.
- CSV, XLSX, GeoJSON, SHP ZIP 업로드의 미리보기와 가져오기를 지원한다. 현재 지원 유형은 건물, 용도지역, 인구, 격자, 에너지다.
- 결측값을 0으로 바꾸지 않고 화면과 계산에서 `자료 없음`으로 유지한다.

### 1.2 확보·적재된 데이터

| 데이터 | 마지막 검증 상태 | 해석상 주의점 |
|---|---:|---|
| EPSG:5179 500m 분석 격자 | 916개 | 프로젝트가 생성한 정렬 격자이며 NGII 공식 격자 ID가 아님 |
| OSM 공동주택 건물 | 2,171개 | 공식 건축물 모집단이 아니며 층수·면적 일부 누락 |
| OSM 경계 | 1개 | 분석용 경계이며 공식 행정경계 원본과 구분 |
| 법정동 코드 | 86개 | 행정표준코드 공개 파일 기반 |
| K-apt 공동주택 | 단지 364개, 양수 연면적 361개 | 목록 기준 2025-12, 상세정보는 수집 시점 값 |
| 전주시 공동주택 공개자료 | 609행 | 준공 595, 공사 중 14 |
| 기상 | DB 전체 16개월, 2025년 12개월 완전 | 2025년 기본값은 ERA5-Land 재분석 자료 |
| 전력 배출계수 | 1개 | GIR 소비단 0.4541 kgCO2eq/kWh; 2025 적용은 프로젝트 방법 |
| 월별 전력·가스 관측 | 0행 | 유효한 서비스 키와 활용 승인 필요 |
| 공식 건축물대장·용도지역·인구 | 각 0행 | 미수집 상태이며 0값으로 해석 금지 |

K-apt 목록·상세, 전주시 공개자료, OSM, 법정동 코드, Open-Meteo ERA5-Land는 별도 API 키 없이 수집·재사용할 수 있다. 외부 서비스 장애나 호출 제한이 있을 때는 저장된 원본을 사용한다.

### 1.3 사용자 기능

- 대시보드, 지도 분석, 분석, 모델, 시뮬레이션, 수집 데이터, 검토 보고서 화면을 구현했다.
- 지도는 경계·건물·격자·선택 격자를 로컬 GeoJSON으로 표시한다. OSM 배경 타일의 403 문제를 수정했고, 타일 장애 시에도 분석 도형과 선택 기능을 유지한다.
- 연도와 선택 격자를 여러 화면에서 공유하고, 동일 범위의 현황·시나리오·보고서를 비교한다.
- FAR/BCR, 세대·인구·녹지·수용량 제약을 검사하고 시나리오 비교와 제약 기반 최적화를 수행한다.
- 모델 학습·교차검증·적격성 판정 코드는 구현되어 있다. 다만 월별 에너지 관측이 0행이므로 현재는 검증된 실데이터 모델 결과를 제공하지 않는다.
- 계산 근거를 고정한 한국어 검토 보고서를 DB에 저장하고 Markdown으로 출력한다.
- 선택형 로컬 Ollama 모델로 근거 문장을 고를 수 있다. 외부 AI API 키는 필요 없고, 모델이 없거나 실패하면 기본 보고서 형식을 사용한다.
- PC가 켜져 있는 동안 Cloudflare Quick Tunnel과 공유 계정으로 무료 HTTPS 시연이 가능하다. 재시작 시 주소가 바뀔 수 있으며 운영용 계정 체계는 아니다.

## 3. API 등의 키만 적용하면 작동할 부분

공공데이터포털에서 **일반 인증키를 발급받고 아래 서비스 각각을 활용신청·승인**한 뒤, 키를 백엔드의 `DATA_GO_KR_SERVICE_KEY`에 설정한다. 키 원문은 Git, 문서, 프런트엔드 환경변수에 넣지 않는다.

| 서비스 | 데이터셋 | 기존 구현 | 키 적용 후 범위와 한계 |
|---|---|---|---|
| 건축HUB 건물에너지정보 | `15135963` | 전기·가스 월별 API, 원본 보존, 정규화, 작업 큐 | 우선 3개 K-apt 지번 후보의 12개월을 제한 수집한다. 전주시 전체 수집은 추가 개발 필요 |
| 건축HUB 건축물대장정보 | `15134735` | 표제부 수집·정규화 어댑터 | 기본 실행은 제한된 법정동/후보와 최대 8개 입력만 처리한다. 전수 수집은 추가 개발 필요 |
| 기상청 ASOS 일자료 | `15059093` | 전주 관측소 146 일자료 수집·월 집계 | 선택 연도 전체를 요청하고 일수가 완전한 월만 ERA5-Land 값을 대체 |

현재 등록된 키는 이전 검증에서 HTTP 403 / 오류코드 30으로 거부되었다. 새 키는 세 서비스의 활용 승인이 모두 완료된 후 적용해야 한다. 키가 유효해도 제공 대상에서 제외된 건물, 해당 기간 자료 부재, 원천기관 장애 때문에 0행이 반환될 수 있다.

키 적용 절차:

1. 저장소 루트의 `.env`에서 `DATA_GO_KR_SERVICE_KEY=` 뒤에 **디코딩하지 않은 일반 인증키**를 입력한다.
2. API와 worker 컨테이너에 새 환경변수를 반영한다.
3. 온라인 모드로 전환하고 제한 수집을 실행한다.
4. 수집 데이터 화면에서 상태, 원본 행 수, 정규화 행 수, 실패 사유를 확인한다.

```powershell
docker compose up -d --force-recreate api worker
docker compose exec -T api python -m app.cli online
docker compose exec -T api python -m app.cli collect --year 2025
docker compose exec -T api python -m app.cli enrich --year 2025
docker compose exec -T api python -m app.cli status
```
K-apt 월별 에너지 API 호출 함수와 단위 검증 테스트는 존재하지만 현재 수집 작업·DB 적재 흐름에 연결되지 않았다. K-apt 에너지 서비스 승인을 받아도 키만 넣어서는 수집 화면에 적재되지 않으므로 2절의 추가 개발 항목으로 본다.

## 권장 진행 순서

1. 공공데이터포털의 건물에너지·건축물대장·ASOS 활용 승인을 받고 키를 교체한다.
2. 위 명령으로 제한 수집을 성공시켜 응답 형식과 실제 제공 범위를 확인한다.
3. 에너지와 건축물대장을 전주시 목표 범위로 확대하고 매칭 품질을 검증한다.
4. VWorld 용도지역과 SGIS/NGII 인구·공식 격자를 전용 어댑터로 통합한다.
5. 가스 계수와 기업 100m 탄소격자를 반영한 뒤 전체 탄소·모델·최적화를 다시 검증한다.
6. 발표용 데이터 스냅샷을 고정하고, 이후 고정 URL의 운영 배포로 전환한다.

신청·다운로드 방법과 필수 필드는 [데이터 재설정·수집 안내](DATA_SETUP_GUIDE.md), 계산 한계는 [알려진 한계](LIMITATIONS.md), 실행·검증 명령은 [테스트 안내](TESTING.md), 배포 구조는 [배포 안내](DEPLOYMENT.md)를 따른다.

## 후속 구현용 프롬프트

아래 내용을 새 작업의 첫 메시지로 그대로 붙여 넣고 중괄호 항목만 채운다.

```text
Carbon Urban DSS 저장소의 후속 구현을 진행해줘.

저장소: C:\Users\ggg\Documents\4학년\캡스톤\선도소프트
기준 문서:
- docs/PROJECT_IMPLEMENTATION_STATUS.md
- docs/DATA_SETUP_GUIDE.md
- docs/LIMITATIONS.md
- docs/TESTING.md

이번에 제공할 키·원본 파일: {{AVAILABLE_KEYS_OR_FILES}}
목표 데이터 범위: {{예: 전주시 전체, 2025년 1~12월}}
배포 목표: {{예: PC 기반 시연 유지 / 고정 서버 배포}}

다음 순서로 실제 코드를 수정하고 검증해줘.
1. 기준 문서와 현재 코드·DB 상태를 먼저 대조하고, 문서의 숫자를 현재 DB 값으로 가정하지 말 것.
2. docs/PROJECT_IMPLEMENTATION_STATUS.md의 미구현 항목 중 제공된 키·파일로 진행 가능한 최우선 항목을 끝까지 구현할 것.
3. API 키는 백엔드 환경변수에서만 읽고 로그·Git·프런트엔드 번들에 노출하지 말 것. 기존 DB 볼륨과 data/raw 원본을 삭제하지 말 것.
4. 원본 응답, 출처, 기준기간, 단위, 좌표계, 요청 파라미터, 수집시각, 정규화 행 수, 실패 사유를 저장할 것.
5. 0과 결측·비공개를 구분하고, 공간·기간·단위가 확인되지 않은 값은 임의로 합산하거나 추정하지 말 것.
6. 백엔드 테스트, 프런트엔드 테스트·빌드, 필요한 실제 API 연동과 브라우저 흐름을 검증할 것.
```
