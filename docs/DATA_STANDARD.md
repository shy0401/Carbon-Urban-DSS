# 공통 데이터 기준 (수집 · 계산 · 보고서)

> **자료를 모으기 전에 이 문서부터 읽습니다.** 팀원 누구나, 어느 지역이든, 사람이 하든 AI 도구로 하든 같은 기준으로 모으고 같은 공식으로 계산해야 결과를 합치고 비교할 수 있습니다. 이 문서가 그 기준의 **유일한 원본**입니다. 코드의 상수·규칙이 이 문서와 다르면 둘 중 하나가 틀린 것이니, 같은 커밋에서 함께 고칩니다(9절).

- 판: 1.0 (2026-10-08) · 근거: [팀 데이터 비교](TEAM_DATA_COMPARISON.md), [탄소 계산](CARBON_METHOD.md), [정확도 점검](ACCURACY.md), 팀 데이터셋 urban-carbon의 `config/rules.yaml`·ADR
- 점검 명령: `docker compose exec api python -m app.cli check-standard` (8절)

## 0. 작업 전 확인 (매번)

1. **범위를 한 줄로 적는다**: 지역(시·군·구 5자리 코드), 기간(YYYY-MM ~ YYYY-MM), 격자(500m), 자료 묶음. 예: `52110 전주시 · 2020-01~2025-12 · 500m · 건축HUB 전 지번`.
2. **이미 있는지 본다**: 앱 **수집 데이터 → 빠진 자료 전부 수집**의 표, 또는 `python -m app.cli status`. 있는 자료를 다시 받지 않는다(일일 한도를 아낀다).
3. **출처를 2절 표에서 고른다.** 표에 없는 출처는 먼저 공식 안내 주소·단위·기준 시점을 확인해 표에 한 줄 더한 뒤(9절) 받는다. 확인 못 한 것은 "확인 필요"라고 적고 짐작으로 채우지 않는다.
4. **키는 `.env`에만** 둔다. 화면·로그·문서·커밋·메신저에 키를 붙이지 않는다.
5. **받는 길은 이 저장소 수집기**(`scripts\dss.cmd Collect / CollectHistory / 지역 준비`)를 쓴다. 직접 받은 파일은 `data/raw/<출처>/`에 그대로 두고 앱의 파일 올리기나 가져오기 명령으로 넣는다.
6. **끝나면** `check-standard`를 돌리고(8절), 공유할 때는 `ExportBundle`, 받을 때는 `MergeBundle`을 쓴다(7절).

## 1. 원칙 여섯 가지

1. **없는 값은 0이 아니다.** 관측이 없으면 NULL(빈칸)로 두고 화면·보고서에 "자료 없음"으로 쓴다. 제공기관이 0을 준 경우만 0이다.
2. **원자료는 고치지 않는다.** 이상한 값은 상태(`quality_status`, 표시 열)로 표시만 하고, 계산에서 뺄지는 규칙(4절)으로 정한다.
3. **값의 종류를 섞지 않는다.** 관측 `OBSERVED` · 공공데이터로 계산 `CALCULATED` · 추정 `ESTIMATED` · 대체 자료 `FALLBACK` · 시나리오 `SCENARIO`를 구분해 저장하고 표시한다.
4. **단위는 이름에 붙인다.** `_kwh`, `_m2`, `_kgco2eq`, `_tco2e`, `_c`, `_persons`. CO2와 CO2eq를 섞지 않는다.
5. **계수·기준값·임계값은 한 곳에서.** 이 문서 5절의 표와 코드 상수(`emissions.py`, `kapt_energy.py`, `area.py`)가 같아야 한다.
6. **출처를 남긴다.** 원본 파일 경로와 SHA-256(`raw_data_assets`), 받은 날, 기준 시점을 기록한다. 보고서의 숫자는 이 기록까지 거슬러 갈 수 있어야 한다.

## 5. 계산 공식

기호: E = 에너지(kWh), C = 탄소(kgCO2eq), A = 연면적(m²), y = 연도, F_e(y) = 그해 전력 계수.

### 5.1 연간 에너지와 칸 집계
- 지번 연간: E_p(y) = Σ_(m=1..12) E_p(y,m), **12개월 모두 있을 때만**.
- 칸 연간: E_g(y) = Σ_(p ∈ 칸 g, 12개월 완비) E_p(y). 지번은 연속지적 필지 대표점이 들어간 칸에 넣는다(`parcel_grid`).

### 5.2 원단위
- I = E / A (kWh/m²·년). A는 **같은 지번에 연결된 건축물대장 연면적의 합**. 연면적이 없는 지번은 분자·분모 모두에서 뺀다.

### 5.3 단위
- 1 tCO2e = 1,000 kgCO2eq, 1 MWh = 1,000 kWh, tCO2eq/MWh = kgCO2eq/kWh.
- 도시가스 부피 → 열량(필요할 때만): 1 Nm³ = 42.7 MJ(총발열량) = 11.86 kWh, 순발열량 38.5 MJ (에너지법 시행규칙 별표).

### 5.4 전력 탄소
- C_e = E_e × F_e(y). **F_e(y) = 그해 12월 31일까지 공표된 가장 최근 GIR 승인 소비단 CO2eq 계수.** 같은 회차에 단년 값과 다년 평균이 함께 나오면 다년 평균을 쓴다.

| 계산 연도 | F_e (kgCO2eq/kWh) | 공표 | 근거 |
|---|---:|---|---|
| 2015~2018 | 없음 (NULL) | — | 이 도구에 원문 없음 |
| 2019~2021 | 0.4594 | 2019-01-02 | 2018 승인 (CO2 0.4567 + CH4·N2O, SAR GWP) |
| 2022~2024 | 0.4781 | 2022-01-10 | 2021 승인 (수정본) |
| 2025 | **0.4330** | 2025-12-18 | 2025 승인, '21~'23 평균 소비단 (단년 2023 값 0.4173을 쓰면 3.6% 작음) |

### 5.5 가스 탄소 (가정)
- C_g = E_g × 0.1826 kgCO2eq/kWh. IPCC 2006 천연가스 CO2 56,100 · CH4 5 · N2O 0.1 kg/TJ, AR5 GWP(28·265) → 0.20256 kgCO2eq/kWh(순발열량 kWh), 건축HUB kWh를 총발열량 기준으로 보고 38.5/42.7을 곱함. **항상 "가정"으로 표시**하고, 전력 탄소와 더한 총량은 가스가 가정임을 함께 적는다. 공식 가스 계수가 확인되면 그 값이 대신한다.

### 5.6 여러 해 비교용 고정 계수
- 개발 전후·추이처럼 **사용량 변화만** 보려는 비교는 모든 연도에 같은 계수(최신 F_e, 지금 0.4330)를 쓴다. 연도별 계수를 쓴 대시보드 값과 다를 수 있음을 함께 적는다.

### 5.7 같은 지번 비교 (두 해)
- 두 해 모두 12개월 계측된 지번 집합 S: Δ% = (Σ_S E(to) − Σ_S E(from)) / Σ_S E(from) × 100.
- 한 해에만 계측된 지번은 곳 수와 kWh를 따로 적는다(합에 섞지 않음). 결측·비교 제외 연도(2020)는 from으로 쓰지 않는다.

### 5.8 개발 전후
- 사용승인 연도 t의 개발: 전 = t−w … t−1, 후 = t+1 … t+w 중 12개월 완비 연도의 평균(w = 2 또는 3). 변화율 = (후 − 전) / 전 × 100.
- 신축 몫 = 새 단지 연평균 / 후 기간 지역 연평균 × 100.
- 관측이 부족하면 추정: 늘어난 연면적 × 지역 관측 원단위, `ESTIMATED`로 표시.

### 5.9 감축 노력 (목표 역산)
- 기준: 기준 연도 b의 관측 E_b, 원단위 I_b (공동주택 = K-apt, 건물 전체 = 건축HUB 계측 지번). 기준을 반드시 함께 적는다.
- 계획 반영(BAU): E_bau = E_b + I_b × (추가 연면적 − 철거 연면적), C_bau = E_bau × F.
- 목표: C_target = E_b × F × (1 − 목표%/100). 필요 감축 ΔC = C_bau − C_target (≤ 0이면 목표 충족).
- 선택지: 신축만 효율화 ΔC / C_new × 100, 전체 효율화 ΔC / C_bau × 100, 재생에너지 상쇄 ΔC / F (kWh/년), 태양광 ΔC / F / 발전량(kWh/kW·년).

### 5.10 기상
- 난방도일 HDD = Σ_일 max(18 − T_일평균, 0), 냉방도일 CDD = Σ_일 max(T_일평균 − **24**, 0) (°C·일, 한국가스공사 냉난방도일 통계 기준). 그달 일평균이 하루라도 비면 그달 도일은 NULL.

### 5.11 모델 검증
- 공간 교차검증(2km 블록), 같은 칸의 다른 연도를 학습·검증에 나눠 넣지 않는다. 오차는 nMAE와 R²를 함께, 표본 수와 함께 적는다.

### 5.12 다른 출처와 맞대기
- 탄소공간지도(모든 건물·tCO2e)와 이 도구(건축HUB 계측 지번·kgCO2eq)는 범위가 달라 **더하지 않고**, 같은 칸끼리 로그 값·순위로 비교한다. 총량은 한전 시군구 전력·지역 인벤토리와 맞댄다([팀 데이터 비교](TEAM_DATA_COMPARISON.md) 2절).

### 5.13 태양광 연 발전량 (추정)
- 1 kW 설비의 연 발전량(kWh/kW·년) = 그 지역 **수평면 일사량**(kWh/m²·년) × **성능비 0.80**. 1 kWh = 3.6 MJ, 설비 1 kW = 1 kW/m²(표준 조건) 기준이다.
- 일사량: 전주는 기상청 ASOS 146 일 합계 일사량(한 해 모든 날이 있을 때), 그 밖과 ASOS가 빈 해는 ERA5 일 일사량(0.25° 재분석, `FALLBACK`). 같은 해면 관측을 쓰고, 분석 마지막 연도 이하에서 가장 최근의 완비 연도를 쓴다.
- 경사 보정을 하지 않는다(경사면은 더 받으므로 필요한 설비 용량이 크게 나오는 쪽). 그늘·방위·설치 면적은 넣지 않는다.
- 사용자가 발전량을 넣으면 그 값을 쓰고 "사용자 입력"으로 적는다. 추정값은 보고서에 **"(추정값)"** 과 연도·일사량·성능비를 함께 적는다. 완비 연도가 없으면 설비 용량은 비운다(0 아님).
- 코드: `backend/app/solar.py` (`PERFORMANCE_RATIO`), 일사량 받기: `python -m app.cli backfill-solar [--region 코드,코드]`.

## 6. 보고서 작성 기준

1. **숫자는 계산 엔진의 근거 문장에서만** 가져온다. 사람·AI가 새 숫자를 만들지 않는다(앱 보고서는 검증기가 근거에 없는 숫자, 증감 방향 오류, 감축 기준 누락을 막는다).
2. 숫자마다 **단위·연도·출처·값의 종류**(관측/계산/추정/시나리오)를 붙인다. "자료 없음"은 0으로 쓰지 않는다.
3. 감축량을 쓸 때는 **기준(공동주택 K-apt / 건물 전체 건축HUB / 추정)과 기준 연도**를 같은 문단에 쓴다.
4. 증감은 같은 지번(5.7)이나 같은 범위끼리만 말한다. 전후 차이를 원인처럼 쓰지 않는다("개발 때문에" ✕, "개발 전후로" ○).
5. 법적 판단(허가 가능 여부)과 넷제로 달성을 단정하지 않는다.
6. 끝에 **한계**(제공 범위 밖 건물, 결측 연도, 가정 계수)와 **출처 표**, **재현 정보**(보고서 ID, 근거 SHA-256)를 둔다. 앱의 검토 보고서·지역 보고서는 이 순서로 자동 작성된다.
7. 팀 발표·문서에 다른 팀원의 자료를 쓸 때는 묶음 이름과 기준일을 적는다(예: "urban-carbon 2026-10-01, 탄소공간지도 2024").

## 7. 저장·공유 기준

| 항목 | 기준 |
|---|---|
| 원본 | `data/raw/<출처>/…`에 받은 그대로. 고치지 않는다. 경로·SHA-256은 `raw_data_assets`에 자동 기록 |
| 표로 주고받을 때 (CSV) | UTF-8. 엑셀용 사본만 BOM. 빈칸 = NULL(“0”, “-”, “N/A”를 쓰지 않음). 열 이름은 영문 소문자_단위. 첫 열들은 키 |
| 키 열 | 에너지: `sigungu_code, bjdong_code, lot_type, bun, ji, use_ym, energy_type` · K-apt: `complex_code, year_month` · 칸: `grid_id`(`cell_x_y`)와 `grid_cd_500m`(SGIS 코드), `year` |
| DB째 주고받기 | 보낼 때 `scripts\dss.cmd ExportBundle`, 받을 때 `scripts\dss.cmd MergeBundle -BundlePath … -DryRun` 후 실제 실행(자기 값은 바뀌지 않고 없는 행만 더함). [팀원 PC 재현](TEAM_SETUP.md) |
| 올리지 않는 것 | `.env`·키, `data/`(원본·DB 덤프·백업), 국토통계지도 자료(국외 반출 금지: Git·클라우드·공개 주소 금지), 개인 설정(`.idea/` 등) |
| 이름 | 묶음·폴더: `<지역코드>_<지역>_<기준일>`, 작업 기록: `docs/<주제>_<날짜>.md` |

## 8. 끝나고 점검

```powershell
docker compose -p carbon-urban-dss -f compose.yaml -f compose.demo.yaml exec -T api python -m app.cli check-standard
# 다른 사람에게 받은 CSV 표를 넣기 전에
docker compose -p carbon-urban-dss -f compose.yaml -f compose.demo.yaml exec -T api python -m app.cli check-standard --csv /data/raw/<폴더>/<파일>.csv
```

`check-standard`는 DB와 파일이 이 문서를 지키는지 셉니다: 음수 사용량, K-apt 미보고 달에 남은 양, 전력 계수 표(5.4)와 등록 계수, 냉난방도일 기준온도(5.10), 원본 파일의 해시, 칸 ID 형식, CSV의 인코딩·빈칸 표기·키 중복·단위 없는 숫자 열. 결과는 `data/ops/standard-check.json`에도 남고, 앱 **사용 방법 → 데이터 기준**에서 볼 수 있습니다. "확인 필요"가 나온 항목은 고치거나, 고칠 수 없는 이유를 작업 기록에 적습니다.
