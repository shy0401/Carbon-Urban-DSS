# 구현 요구사항 및 범위

## 기능

F01 대시보드는 DB에 저장된 선정 격자, 기본 기준연도 2025, 월별 에너지·기상·출처 상태를 조회한다. 결측은 null이다.

F02 지도는 전주시 경계, 500m 격자, 공동주택 도형, 선정 격자를 렌더링한다. 관측 지번과 좌표가 연결된 소비량만 격자에 집계한다. 격자 전체 건물의 소비량을 확보했다고 해석하지 않는다.

F03 수집 센터는 출처·원본·정규화 행·해시·이력·실패·품질을 표시하며, 에너지와 기상 기간 수집을 Celery 작업으로 요청한다. 수집 이력은 DB에 남는다.

F04 수동 파일은 미리보기와 필드 매핑 확인 후 가져온다. 사용자 제공자·URL은 공식성을 자동 보장하지 않는다. 원래 좌표계·원본 도형·정규화 도형을 보존한다.

F05 시뮬레이터는 개발가능 부지, 동수·건축면적·층수·세대수·인구·효율·PV·녹지비율을 받아 FAR/BCR 및 확보된 에너지 원단위 추정을 계산한다. 입력 계획과 결과는 별도 테이블에 남는다.

F06 최적화는 동수와 3~40층을 열거하고 수용량·공간 조건을 검사한다. 검증된 법적 제한이 없으면 법적 최적안으로 표시하지 않는다. 기준 관측이 부족하면 최적안 대신 부족 사유를 반환한다.

F07 모델 화면은 에너지원별 표본·변수·검증 조건·실제 검증 결과를 표시한다. 충분한 공간 표본이 없으면 ML 검증 성공을 주장하지 않는다.

F08 오프라인 모드는 새 외부 데이터 요청을 차단하고 기존 DB·캐시를 사용한다.

## 비기능·데이터·GIS

- Python3.12, React/TypeScript, PostgreSQL16/PostGIS, Redis/Celery, Docker Compose의 다섯 서비스를 사용한다.
- 격자 기준은 EPSG:5179, 길이500m, 넓이250,000m²이다. GeoJSON 응답은 EPSG:4326이다. 경계와 교차하는 셀을 자르지 않는다.
- 파일캐시 키에는 공급자·operation·지역·월·페이지·공개 요청 파라미터가 포함된다. 서비스키는 저장 키와 메타데이터에서 제외한다.
- 인증 오류는 사이트 전체 실패로 전파하지 않는다. 기존 원본·정규화 데이터는 보존한다.
- `OBSERVED`, `CALCULATED`, `ESTIMATED`, `FALLBACK`, `SCENARIO`를 분리한다. 결측 보정을 수행하지 않으면 `IMPUTED` 자료를 만들지 않는다.
- 수집·업로드 상한, 제한된 동시성, 재시도/backoff로 외부 API 트래픽을 제한한다.

## 보안 및 운영

서비스키는 backend/worker 환경에만 존재한다. frontend 번들·로그·Git에 포함하지 않는다. API와 웹 포트는 localhost에만 바인딩한다. 외부 배포용 사용자 인증·역할 관리는 구현 범위 밖이다. 원본 다운로드와 업로드는 지정된 data 디렉터리 내부에 보관한다.

## 검증 범위

현재 확인된 구현과 미충족 외부 의존성은 FINAL_REPORT.md 및 LIMITATIONS.md를 우선한다. 문서의 요구 문장은 모든 데이터가 확보되었다는 성공 선언이 아니다.

F09 동일 연도·격자의 최대 3개 저장 계획안을 한국어 보고서로 비교하고, 생성 시점의 계산·출처 스냅샷과 해시를 보존한다. Markdown 및 인쇄/PDF를 제공한다.
F10 선택형 로컬 AI는 검증된 근거 문장만 선정한다. 연결 또는 응답 검증 실패 시 기본 서식으로 대체한다. 최신 구현·미구현 구분은 IMPLEMENTATION_UPDATE.md를 따른다.
