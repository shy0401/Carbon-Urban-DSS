# 입력 데이터 → 산출 데이터·보고서 명세와 방향성 검토

- 작성: 2026-09-23 (Claude)
- 목적: "어떤 데이터가 주어지면 어떤 데이터와 보고서가 나와야 하는가"를 한 곳에 고정하고, 현재 구현이 그 방향과 맞는지 점검한다.
- 기준: [SRS](SRS.md), [탄소 계산](CARBON_METHOD.md), [모델](MODEL_VALIDATION.md), [시나리오](SIMULATION_METHOD.md), 2026-09-23 실측 DB

## 1. 이 시스템이 답해야 하는 질문

| # | 의사결정 질문 | 최종 산출물 |
|---|---|---|
| Q1 | 전주시 주거지의 **현재** 운영에너지·운영탄소는 얼마이고 어디(500m 격자)에 집중되는가? | 격자·단지별 월/연 에너지(관측), 전력 탄소, 원단위 지도 |
| Q2 | 그 값은 **어떤 도시 조건**(용도지역, 인구, 건물 규모·연식, 기상)과 함께 나타나는가? | 격자 맥락 지표(용도지역 비율, 행정동 인구, 단지 세대·연면적), 기상 보정 변수 |
| Q3 | 특정 대상지(격자)를 **정비·재개발한다면** 계획안(동수·층수·효율·PV)에 따라 운영탄소가 어떻게 달라지는가? | 계획안별 FAR/BCR·세대수·연간 에너지·탄소 비교, 최적안(에너지 기준) |
| Q4 | 그 판단은 **얼마나 믿을 수 있는가**? | 출처·기간·단위·공간 매칭률·결측, 모델 공간 교차검증 지표, 법적 한계 |

모든 수치는 `OBSERVED`(관측) · `CALCULATED`(관측×공식 계수/면적) · `ESTIMATED`(모델) · `SCENARIO`(계획 가정) · `FALLBACK`(대체 자료)을 구분해 표시한다. 관측 0행은 사용량 0이 아니다.

## 3. 처리 과정과 산출 데이터셋

```text
원본(API 응답·파일, SHA-256 보존)
 → 정규화: 단지×월 / 지번×월 / 일→월 기상 / 행정동 통계 / 용도지역·필지 도형   [OBSERVED]
 → 공간 연결: 단지 좌표·지번 → 500m 격자 (매칭 방법·신뢰도 기록, 모호하면 보류)
 → 격자×월 에너지 합계 (에너지원별, 관측 단지 범위)                               [OBSERVED 합계]
 → 매칭 연면적(같은 단지 집합이 12개월 모두 관측된 경우만)                          [CALCULATED]
 → 탄소 = 관측 kWh × 공식 계수 (에너지원별, 계수 없는 에너지원은 null)             [CALCULATED]
 → 원단위 = 연간 kWh / 매칭 연면적, 세대당 = 연간 kWh / 매칭 세대수                  [CALCULATED]
 → 모델: 월별 원단위 ~ 계절·HDD/CDD(+규모·연식), 2km 공간 블록 교차검증            [ESTIMATED]
 → 시나리오: 계획 연면적 × 관측 원단위 × 효율 × (1−PV), FAR/BCR, 세대·인구 수용량   [SCENARIO]
 → 보고서 스냅샷(근거 해시)
```

| 산출 데이터셋 | 행 단위 | 핵심 컬럼 | 저장 위치 |
|---|---|---|---|
| 단지 월별 에너지 | 단지×월 | 전기 kWh·가스 m³·난방 Mcal·급탕, 전기 탄소, 품질상태 | `apartment_energy_monthly` |
| 지번/단지 월별 관측 | 지번×월×에너지원 | kWh, 격자, 매칭 방법, 출처(건축HUB 우선) | `energy_monthly` |
| 기상 월 | 월 | 평균기온, HDD/CDD, 출처(KMA 완전월 우선, ERA5 대체) | `weather_monthly` |
| 격자 맥락 | 격자 | 용도지역 비율(주거·상업·공업·녹지), 요청 여부 | `grid_zoning_stats`, `vworld_grid_coverage` |
| 행정동 맥락 | 행정동 | 인구·가구, 비공개/결측 상태, 경계 | `sgis_*` |
| 모델 실행 | 실행 | 표본수, 격자·블록·월 수, MAE/RMSE/R²/NMAE | `model_runs` |
| 계획안 | 계획안 | 입력, FAR/BCR, 월별 에너지·탄소, 기준 대비 차이 | `scenarios`, `scenario_results` |
| 보고서 | 보고서 | 근거 문장, 대상지 공식 현황, 출처, 비교, 해시 | `decision_reports` |

## 6. 방향성 검토

**맞게 가고 있는 점**
- 출처·단위·결측·품질 라벨을 분리하고, 관측이 없으면 값을 만들지 않는 원칙이 코드·화면·보고서에 일관되게 적용되어 있다.
- 500m 격자 기준으로 관측 → 계산 → 계획안 → 보고서가 한 흐름으로 연결되고, 보고서는 근거 해시로 재현된다.
- 이번에 공식 맥락(용도지역·행정동 인구·단지 규모)이 지도·분석·보고서에 실제로 연결되었다.

**방향 조정이 필요한 점**
1. **범위 명칭**: K-apt는 의무관리 공동주택, 건축HUB 에너지는 단독주택·200세대 미만을 제외한다. 산출물은 "전주시 주거 전체"가 아니라 **"관측 가능한 공동주택 운영에너지"**로 이름 붙여야 한다(격자 합계 ≠ 격자 전체 소비).
2. **최종 성과(탄소 감축)의 병목은 가스 계수**다. 데이터가 모두 와도 가스 계수 방법을 정하지 않으면 전체 탄소·감축률은 계속 null이다. → 건축HUB 가이드(.hwp)에서 kWh 환산 열량 기준(총/순발열량)을 확인하고, GIR 도시가스 계수(CO₂·CH₄·N₂O, GWP)를 정하는 결정이 필요하다.
3. **계획안 효과의 근거**: 현재 시나리오는 "관측 원단위 × 계획 연면적 × 효율 배율 × (1−PV)"다. 효율 배율·PV 비율을 자유 입력으로 두면 결과가 가정에 좌우된다. 제로에너지건축물 등급 등 **출처 있는 프리셋**으로 제한하는 것이 발표·심사에 유리하다.
4. **법적 검토**: 용도지역은 확보했으나 용도지역별 FAR/BCR 상한(전주시 도시계획 조례)이 없어 "에너지 최적안"까지만 가능하다. 조례 표를 공식 근거로 넣으면 계획안 적법성까지 한 번에 보여줄 수 있다.
5. **시점 정합성**: 에너지 2025, SGIS 2024, 용도지역·지적은 수집 시점. 보고서가 이미 기준기간을 표기하지만, 비교 시 시점 차이를 한계로 명시해야 한다.
6. **발주처 기대 산출물 확인**: 선도소프트 100m 탄소격자와 비교 가능한 형식(격자 크기·지표·단위)이 최종 납품 기준일 가능성이 높다. 500m 결과를 100m 격자 집계와 대조할 수 있도록 원본·명세를 먼저 받는 것이 좋다.

## 7. 팀이 정해야 할 것

| 결정 | 선택지 | 영향 |
|---|---|---|
| 가스 탄소 방법 | GIR 도시가스 계수 + 건축HUB kWh 열량 기준 확인 / 가스 제외 유지 | 전체 탄소·감축률 산출 여부 |
| 분석 대상 범위 명칭 | 공동주택 한정 명시 / 단독주택 추정 추가(ESTIMATED) | 결과 해석과 보고서 제목 |
| 계획안 파라미터 | 자유 입력 / 출처 있는 프리셋 | 결과의 설득력 |
| 법정 상한 | 조례 표 입력 / 미확정 유지 | 적법성 검사 가능 여부 |
| 최종 격자 | 500m 유지 / 100m 병행 | 발주처 산출물 호환 |
