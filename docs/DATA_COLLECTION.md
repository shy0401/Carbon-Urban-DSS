# 수집과 업로드

|---|---|---|---|---|
| 건축HUB 건물에너지 (15135963) | **2024-01부터** (2015~2023년은 모든 달이 빈 응답) | 법정동 × 월, 번·지를 빈 값으로 보내면 그 동의 모든 계측 지번(100행/페이지) | 10,000 | 약 4,000 (83개 법정동 × 12개월 × 전기·가스 × 페이지) |

- 건축HUB는 번·지를 비워 **법정동 단위로 전 지번**을 받는다. 공동주택 298개 지번을 하나씩 부르는 방식(연 6,500 호출)보다 적은 호출로 상가·업무·학교·대형 공동주택까지 받는다. 단독주택, 200세대 미만 공동주택(2020년~), 산업·수송·발전용은 제공기관이 빼고 준다.
- K-apt 과거 11년치는 개발계정으로 하루 약 1년치씩, 열흘 넘게 걸린다. 공공데이터포털에 활용사례를 등록하고 운영계정 트래픽 증가를 신청하면 빨라진다.
- K-apt 게이트웨이의 `04 HTTP_ERROR`는 **일부 백엔드 서버**에서 나오고, 한 번 연결(keep-alive)된 서버에 계속 붙는다. 2026-09-26 실측: 같은 20개 단지·월을 한 연결에서 0/20, 다른 연결에서 20/20, 새 연결마다 약 절반 성공. 그래서 한 연결이 나쁜 서버에 붙으면 한 시간 동안 311개 단지 중 218개가 실패했다. 이제 오류가 나면 **새 연결로 다시 요청**한다(한 달 최대 3번). 그래도 실패가 8번 연속되면 3분 쉬고(최대 20번), 한 해를 다 돈 뒤 여전히 실패한 달만 10분 뒤 다시 묻는다(2회). 그래도 한 해의 5% 넘는 달이 남으면 그 해는 `PARTIAL`(다시 시도)로 두고, 작업이 2시간 기다렸다가 스스로 이어서 남은 달만 다시 묻는다(한 해 최대 3회차). 3회차 뒤에도 남은 달은 `FAILED`로 남긴다. 실패한 달을 0으로 채우지 않는다.
- 과거 수집 순서는 최근 연도부터, 연도마다 SGIS → ASOS → 건축HUB, 그다음 한 번 받는 레이어, K-apt는 맨 끝이다. 한도에 걸리면 그 자료만 멈추고 다음 날 00:20(KST)에 이어서 받는다.

## 빠진 자료 전부 수집 (2026-09-25)

수집 데이터 화면 맨 위에서 시작·끝 연도를 정하고 **빠진 자료 전부 수집 시작**을 누른다. PC에서는 `scripts\dss.cmd CollectAll -FromYear 2015 -ToYear 2025`로 같은 일을 하며, 이 명령은 백업을 먼저 만든다.

- 연도별·자료별 상태표: 완료 / 수집 예정 / 다시 시도 / 미공표 / 키·승인 필요
- 이미 DB에 있는 항목과 키가 없는 자료는 호출하지 않는다.
- 일일 한도에 걸리면 다음 날 00:20(KST)에 자동으로 재개한다.
- 상세 설명은 웹 **사용 방법 → 자료 수집**과 [AREA_SIMULATION.md](AREA_SIMULATION.md)에 있다.

## 자동 수집

수집 데이터 화면에서 에너지/기상과 시작·종료월을 선택한다. 기본은2025년, 작업당 최대12개월이다. 장기간은 연도별로 나누어 요청한다. 현재 지원 지역은 전주시이며 전국 수집은 실행하지 않는다.

`POST /api/v1/collection-jobs`는 `source`, `start_month`, `end_month`, `region`을 받는다. `GET /api/v1/collection-jobs`와 `/{id}`는 DB 작업상태를 제공한다. 기존 `/api/collections`도 제공한다.

원본 응답은 파일 캐시에 보존한다. 성공한 과거 동일 요청은 재호출하지 않는다. 인증 실패는 짧은 오류 캐시에 보존하며, 키를 변경하면 새로운 인증으로 검사를 시도할 수 있다. 외부 오류 응답을 빈 성공으로 정규화하지 않는다.

건축물대장과 KMA 관측은 같은 포털키를 사용하더라도 **별도 서비스 활용 승인**이 필요하다. 건축물대장 표제부 전체 수집은 위의 '빠진 자료 전부 수집' 또는 개별 수집의 `building_register`로 실행한다. 이전 어댑터(최소 확인용):

```powershell
docker compose exec api python -m app.cli enrich
```

## 수동 파일

수집 데이터의 파일 업로드에서 CSV, XLSX, GeoJSON, SHP 구성파일 ZIP을 선택한다. 원본 CRS가 감지되지 않으면 직접 지정한다. 파일 유형·열·미리보기·경고를 확인한 뒤 대상 필드와 매핑한다. 제공기관, 공식 원문 URL, 기준기간도 입력한다.

25MB 업로드·100MB 압축 해제 상한을 적용한다. 경로 탈출 ZIP과 잘못된 도형을 거부한다. 전체 행 검증 후 하나의 DB 트랜잭션으로 가져온다. 입력 파일은 `data/uploads/`에 보존하며 `UNVERIFIED`로 구분한다. URL을 적었다는 이유만으로 공식 인증 배지를 부여하지 않는다.
