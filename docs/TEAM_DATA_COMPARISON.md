# 팀원 데이터와 이 도구 데이터 비교 (2026-10-08)

세 묶음을 같은 질문으로 맞대어 본 결과입니다. 숫자는 PC DB와 팀 공유 폴더의 파일을 직접 읽어 셌습니다. 앞으로 새로 모으는 자료는 [공통 데이터 기준](DATA_STANDARD.md)을 따릅니다.

| 묶음 | 위치 (PC, Git 제외) | 만든 방법 |
|---|---|---|

| **B. urban-carbon** (팀 데이터셋) | `urban-carbon_공유_전체_2026-10-01_윤영준\` | 팀원 저장소 `urban-carbon` (Python 파이프라인, 설정 `config/*.yaml`, ADR 26개) |

## 2. 같은 칸에서 맞대 본 값 (전주, A 건축HUB vs B 탄소공간지도)

A의 칸별 전력(12개월 계측 지번 합 × 그해 공표 계수 0.4781)과 B의 칸별 전력 배출량을 같은 500m 칸끼리 비교했습니다.

| 연도 | B 칸 | 둘 다 값 있음 | B에만 값 | 합계 A / B | 칸별 비율 중앙값 (10~90%) | 상관(로그) | 상관(원값) |
|---|---:|---:|---:|---:|---:|---:|---:|
| 2022 | 918 | 587 | 327 | 0.51 | 0.67 (0.08~1.17) | 0.85 | 0.11 |
| 2024 | 918 | 592 | 312 | 0.84 | 0.76 (0.14~1.14) | 0.91 | 0.92 |

- 칸의 크기 순서는 잘 맞습니다(로그 상관 0.85~0.91). 이 도구 값이 대체로 작은 것은 **건축HUB가 단독주택·200세대 미만 공동주택을 주지 않기 때문**입니다. B에만 값이 있는 칸 312~327개가 주로 그런 칸입니다.
- 2022년 원값 상관이 0.11인 것은 B의 몇몇 큰 칸(산업단지 등) 때문입니다. B 문서도 이 해의 큰 사용처와 가스에 원자료 문제를 적어 두었습니다. 그래서 두 묶음을 맞댈 때는 로그 값이나 순위로 비교하고, 합계는 같은 범위(같은 건물 묶음)인지 먼저 확인합니다.
- 결론: **총량은 B(모든 건물), 지번·월 단위 변화와 개발 전후는 A(관측 에너지)** 로 봅니다. 두 값을 섞어 더하지 않습니다.

## 3. 맞춰야 했던 기준 (이번에 정한 것)

| 항목 | 다르던 점 | 이제의 기준 | 반영 |
|---|---|---|---|
| 냉방도일 기준온도 | A 18°C, B 24°C | 난방 18°C · 냉방 24°C (가스공사 냉난방도일 통계 기준) | A의 수집기와 저장된 값을 다시 계산 |
| 탄소 단위 | A kgCO2eq, B tCO2e | 저장은 kgCO2eq, 표·보고서는 단위를 열 이름·머리에 적음. 1 tCO2e = 1,000 kgCO2eq | [기준 5절](DATA_STANDARD.md#5-계산-공식) |
| 2025년 전력 계수 | A는 2024 승인(0.4541)을 2025에 씀 | 그해 말까지 공표된 최신 승인 계수: 2025년은 2025 승인 '21~'23 평균 0.4330 | 계수 등록, 화면 문구 |
| 격자 ID | `cell_x_y` vs `다마71b61b` | 둘 다 EPSG:5179 왼쪽 아래 좌표에서 계산되는 같은 칸. 교환 파일에는 둘 다 적음 | [기준 3절](DATA_STANDARD.md#3-지역격자시간-기준) |
| 자료 문제 표시 | 서로 다른 규칙 | 값은 고치지 않고 표시만. 두 묶음의 표시 규칙을 기준 문서 한 곳에 모음 | [기준 4절](DATA_STANDARD.md#4-값-처리-규칙) |
