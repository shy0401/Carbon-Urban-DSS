당신은 Carbon Urban DSS의 다음 개발·운영 담당자다. 목표는 현재 구현을 검증하고, 부족한 작업을 의존성 순서대로 직접 수행해 전주시 2025년 실데이터 기반 의사결정 프로토타입의 완성도를 높이는 것이다. 설명만 하고 멈추지 말고, 접근 가능한 코드·DB·테스트·문서 작업을 끝까지 진행하라.

일의 순서:
A. 데이터 보존을 먼저 확인하고 복구 가능한 백업을 만든다. 현재 DB를 덮거나 지우는 조치는 복원 검증 전 수행하지 않는다.
B. 팀원 PC에서도 같은 저장소와 승인된 데이터를 재현할 수 있게 Windows 초기 설정·사전 검사, PostgreSQL/원본의 안전한 내보내기·가져오기, 체크섬 검증, 새 PC 실행 안내를 구현한다. Git clone만으로 DB·raw·API 키·AI 모델이 전송되지 않는다는 점을 해결하되 .env/.secrets/캐시/임시 공개 URL을 공유 묶음과 Git에서 제외한다. 깨끗한 별도 환경에서 복원과 웹·API·지도까지 검증한다.
C. 최종 실증의 핵심인 K-apt 2025년 월별 에너지를 최우선 데이터 과제로 다룬다. 현재 확인된 공공데이터포털 키는 403/코드 30으로 거절되었고 월별 관측은 0행이었다. 승인 키가 이미 제공되었는지 값은 출력하지 않고 상태만 확인하라. 유효하면 1단지×1개월 SMOKE → 3단지×12개월 LIMITED → 전주시 전체 FULL로 확대하고 성공 월 재호출을 피하라. 각 단계에서 HTTP/제공기관 코드, 원본, 정규화 행, 전기 kWh·가스 m³ 등 단위, 지점·격자 매칭, 결측, 호출 수를 검증하라. 유효한 키가 없으면 계정 소유자에게 필요한 서비스 승인과 환경변수 이름만 한 번 명확히 요청하고, B 및 다른 독립 작업을 계속 진행하라.
D. KMA ASOS, SGIS, VWorld, 건축HUB는 각각 현재 키·승인·원본 상태에 맞춰 작은 실제 응답부터 검증하라. SGIS 행정 인구를 500m 격자에 임의 배분하지 말고 공식 경계·ID·기준연도·비밀보호 표식을 확보해야 한다. VWorld는 현재 설정 레이어와 geometry/CRS/페이지를 확인하라. 기업 100m 탄소격자는 원본·단위·포함 부문·이용조건이 확보되기 전 계산에 넣지 마라.
E. 확보된 동일 관측 범위에서만 전기 탄소, 검증된 가스 계수, 모델 성능을 계산하라. 관측 0행을 사용량 0으로 표시하지 말고 모의 테스트를 실데이터 검증이라고 보고하지 마라. 부족한 표본·근거가 있으면 화면과 보고서에 명시하라.
F. 소스 중복 표시, 초기 JS 번들 경고, DB 마이그레이션·인증·백업 운영 등 남은 품질 작업을 중요도에 따라 수행하라. 범위가 크면 사용 가능한 데이터와 팀원 PC 재현부터 완료하고 나머지를 증거와 함께 백로그로 남겨라.

필수 작업 방식:

- 백엔드 pytest 전체, 프런트엔드 Vitest와 운영 빌드, 관련 E2E, DB 행 수와 원본 해시, 공개 접속을 가능한 환경에서 검증하라. 실행하지 못한 검사는 이유를 기록하라.
