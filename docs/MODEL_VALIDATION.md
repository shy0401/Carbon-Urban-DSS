# 모델 방법과 검증

현재 서비스의 시나리오 모델은 월별 관측kWh/매칭된 연면적을 사용하는 `INTENSITY_ESTIMATE`다. 학습된 AI 예측으로 부르지 않는다. 기준연면적 또는 에너지가 없으면 값을 만들지 않는다.

추가 비교는 에너지원별 최소120 관측,10개 격자,3개2km 공간 블록,10개 월을 갖춘 자료에서만 실행한다. 이 문턱은 최소 안전장치이며 검증 정확도 보증이 아니다. 전체 건물면적을 임의의 관측 부분집합 분모로 사용하지 않는다.

## 학습 행 (격자 × 월)

지도 원단위와 같은 규칙(`model_service.model_rows`)으로 만든다.

- 격자별로 K-apt 단지와 매칭된 지번 중 **12개월 모두 관측**된 지번만 쓴다.
- 단지 연면적은 `floor_area_status`를 통과해야 한다(세대당 20~400m², 관리비부과면적 이상). 예: 연면적 152,757,779m²로 공표된 단지는 제외.
- 전력은 세대당 연 600~18,000kWh 밖이면 제외한다(공용부만 계량되었거나 다른 건물이 섞인 지번).
- 격자의 에너지와 연면적은 **같은 지번 집합**에서 나온다. 매달 같은 지번이다.
- 격자 변수: 세대당 연면적(단위세대 크기), 사용승인 후 경과연수(연면적 가중). 값이 하나라도 없는 격자가 있으면 그 변수는 비교에서 뺀다(채우지 않음).
- 난방방식: 격자별 **지역난방 연면적 비율**(난방방식 미상 단지는 지역난방이 아닌 것으로 셈)을 특성으로 넣는다. 모든 격자의 값이 같으면(전주 가스처럼 거의 개별난방) 구분력이 없어 뺀다. 기준 모델(월별 평균 원단위)도 이 특성이 있으면 (월, 지역난방 비율 ≥ 0.5) 묶음별 평균을 쓴다.

비교 후보는 월별 원단위 기준, ElasticNet, RandomForestRegressor, HistGradientBoostingRegressor, spline+Ridge 가산모형이다. 공간 블록 GroupKFold를 사용하고 전처리는 각 학습 fold에서만 적합한다. 검증 대상은 보류한 공간 블록이며 학습 정확도를 성공 기준으로 사용하지 않는다.

지표는 kWh로 환산한 MAE,RMSE,R²,NMAE,sMAPE와 **원단위 R²**(kWh/m²·월 기준)다. NMAE와 sMAPE는0–1 비율이며 상수 관측에서R²는 미정의/null이다. 총량 R²는 격자 연면적 크기만으로도 높게 나오므로, 격자 사이 원단위 차이를 설명하는 정도는 원단위 R²로 본다(월별 값이라 계절 변동도 포함). 실제 실행 결과만 `model_runs`에 저장한다.

## 실측 검증 결과 (PC Docker, 2026-09-26)

건축HUB 전 지번 월별 에너지(2024·2025)와 K-apt 단지 매칭으로 만든 학습 행으로 `/api/model/validate`를 실행한 결과다. 2km 공간 블록 28개, GroupKFold 5겹, 검증 폴드 값.

| 연도·에너지 | 행(격자·월) | 격자 | 가장 작은 MAE 모델 | MAE kWh/격자·월 | nMAE | R² 총량 | R² 원단위 | 기준(월별 평균 원단위) nMAE / R² 원단위 |
|---|---:|---:|---|---:|---:|---:|---:|---|
| 2025 전력 | 1,608 | 134 | RandomForest | 38,484 | 9.1% | 0.962 | 0.56 | 9.9% / 0.46 |
| 2025 가스 | 1,644 | 137 | RandomForest | 79,147 | 10.8% | 0.966 | 0.92 | 19.1% / 0.86 |
| 2024 전력 | 1,572 | 131 | spline+Ridge | 38,852 | 9.0% | 0.962 | 0.61 | 10.0% / 0.57 |
| 2024 가스 | 1,656 | 138 | RandomForest | 84,241 | 11.8% | 0.954 | 0.90 | 19.7% / 0.84 |

해석:

- 가스는 세대당 연면적·경과연수를 넣은 모델이 월별 평균 원단위 기준보다 오차를 절반 가까이 줄였다(nMAE 19%→11%).
- 전력은 개선 폭이 작다(10%→9%). 보류한 공간 블록의 월별 전력 원단위 변동 중 절반 정도만 설명된다(원단위 R² 0.46~0.61). 거주 행태·가전 등 자료에 없는 요인이 크다.
- 이 결과는 **공동주택(K-apt 매칭 지번)** 에 대한 것이다. 상가·업무 건물이나 격자 전체 건물에는 적용하지 않는다.
- 시뮬레이션은 여전히 관측 원단위(`INTENSITY_ESTIMATE`)를 쓴다. ML 비교는 참고 검증이며 자동 승격하지 않는다.
- 예전 저장 검증(2026-09-25, R² 약 -7,889)은 연면적 오기 단지와 공용부 계량 지번이 섞인 학습 행 때문이었다. 위 규칙으로 고친 뒤 다시 실행했다.

## 재측정 (PC Docker, 2026-09-30, 수원 포함·난방방식 반영)

| 지역·에너지 | 행(격자·월) | 격자 | 가장 작은 nMAE 모델 | nMAE | R² 총량 | R² 원단위 | 기준 nMAE / R² 원단위 |
|---|---:|---:|---|---:|---:|---:|---|
| 전주 2025 전력 | 1,656 | 138 | RandomForest | 9.4% | 0.960 | 0.54 | 10.1% / 0.44 |
| 전주 2025 가스 | 1,644 | 137 | RandomForest | 10.8% | 0.966 | 0.92 | 19.1% / 0.86 |
| 수원 2025 전력 | 2,448 | 204 | spline+Ridge | 14.8% | 0.902 | 0.23 | 16.0% / 0.19 |
| 수원 2025 가스 | 1,872 | 156 | RandomForest | 40.4% | 0.850 | 0.88 | 55.3% / 0.80 |

- 수원은 지역난방 단지(258곳, 가스 원단위 중앙값 3.0kWh/m²)와 개별난방 단지(188곳, 71.8)가 섞여 있다. 난방방식을 넣기 전 수원 가스는 기준 nMAE 169%, 최선 모델 127%(총량 R² −0.35)였다.
- 수원 가스 오차가 큰 것은 지역난방 격자의 가스가 작아 같은 절대오차도 비율로 크게 보이기 때문이다. 수원 가스 추정은 참고용이다.
- 여름 격월 고지로 한 달이 빠진 가스 지번(수원 약 2,000곳)은 달별 값이 두 달 치라서 월별 학습 행에 넣지 않는다(연간 합계에는 넣음, [정확도 평가 8절](ACCURACY.md)).

```powershell
docker compose exec api python -m app.cli validate-models --year 2025
docker compose exec api python -m app.cli validate-models --year 2025 --region 41110
```

실제 사용량 자료가 없거나 매칭표본이 부족하면 상태는 `INSUFFICIENT_TRAINING_DATA`, 지표는 null이다. 입력 변수 후보 중 자료가 없는 인구·세대·연령·층수·FAR·BCR를 조작해 넣지 않는다. 상세 상태는 `/model` 및 최종 실행 보고서를 참조한다.
